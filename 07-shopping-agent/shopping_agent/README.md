# 购物助手 Agent

一个能跑起来的完整 Agent 工程：浏览器界面配好模型就能对话，
自带数据集，包含导购、订单、售后三条支线，以及一套三层记忆系统。

```
pip install -r requirements.txt
python run.py
```

浏览器会自动打开 `http://127.0.0.1:8765`。**不配模型也能跑** ——
会走内置的规则实现，链路完整，只是回答比较死板。右上角「模型设置」里
填上任意 OpenAI 兼容端点的地址和密钥，就换成真实模型。

## 数据集

7 个 JSONL，全是构造的演示数据，商品与品牌均为虚构。

| 文件 | 条数 | 说明 |
|---|---|---|
| `products.jsonl` | 40 | 商品（耳机 20 / 键盘 12 / 显示器 8），`specs` 是异构字典 |
| `users.jsonl` | 5 | 用户档案（偏好、回避、身体条件、常去场景） |
| `orders.jsonl` | 12 | 历史订单 |
| `logistics.jsonl` | 12 | 物流轨迹 |
| `policies.jsonl` | 27 | 平台规则，带 `scope` 支持先过滤再排序 |
| `reviews.jsonl` | 60 | 评价，带标签，支持「差评集中点」聚合 |
| `promotions.jsonl` | 10 | 促销规则，带 `stackable` 与生效时间 |

想换成自己的数据：字段对齐 `src/models.py` 里的模型即可，代码不用动。

## 记忆系统

三层，各写各的、各存各的：

| 层 | 装什么 | 生命周期 | 什么时候写 |
|---|---|---|---|
| 会话摘要 | 这个会话聊过什么 | 跟着会话 | 消息超过阈值时压缩 |
| 用户画像 | 用户是谁、稳定偏好 | 长期，会衰减 | 抽到偏好时按 key 覆盖 |
| 事件记忆 | 发生过哪些具体的事 | 中期，按时间衰减 | 每轮结尾，有信号才写 |

几条设计上的取舍，都在 `src/memory.py` 的注释里：

- **不是每轮都写记忆。** 先过一个字符串匹配的信号检测器，
  大多数日常寒暄没有可记的东西，为它们各花一次模型调用不划算。
- **同一件事反复提到会变强，用户改口要够强的证据才翻转。**
  随口一句「这个牌子也行」不该推翻之前明确的偏好。
- **用过的记忆会加分，长期不用的会沉降。** 排序是
  `置信度 × 时间衰减 × 与当前话题的相关度`。
- **遗忘是软删除。** 停用而不删，用户再提起时带着旧证据回来。

左侧面板可以实时看到三层记忆的内容、置信度、命中次数，也能手动删。

## 护栏

三条，都写在代码里，不写在提示词里：

| 护栏 | 落点 | 行为 |
|---|---|---|
| 幂等 | `src/guard.py` + SQLite | 同一笔下单请求重放，第二次返回原结果，不产生第二笔订单。**重启也拦得住** |
| 金额确认 | `src/agents/loop.py` | 超过阈值的订单抛中断，等人在界面上点确认 |
| 轮数上限 | `src/agents/loop.py` | 单支线循环有上限，到顶就把已有信息交出去 |

金额阈值和轮数上限都在设置里可调，方便现场看效果。

## 接本地模型

以 LM Studio 为例：

1. 在 LM Studio 里加载一个模型，启动本地服务（默认 `127.0.0.1:1234`）
2. 页面上打开「模型设置」，选预设「LM Studio（本地）」
3. 点「拉取列表」选模型，或直接点「测试连接」

工具调用需要模型支持 function calling。7B 以上的指令微调模型一般都可以；
如果模型不支持，系统会自动退化为「要一段 JSON 再解析」的方式。

Ollama、DeepSeek、通义、硅基流动、OpenAI 都在预设里，换一个按钮就切过去。

## 已知边界

- 检索是字面匹配的 BM25。用户的口语说法（「三百以内」「新手用」）命中不了，
  这时会退回按结构化条件列出，结果不精准，代码里如实标了这一点。
- 「显示器有坏点能不能换」这类短查询会被泛词稀释，排序不稳。
  这是 BM25 的边界，没有用向量检索去掩盖它。
- 只跑单个进程。多进程部署时幂等和记忆的 SQLite 要换成服务端存储。
